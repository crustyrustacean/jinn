Present the run to the human for QA — the G2 gate. The human tests
behavior; nobody reviews code with them.

## The brief

Write it in the ledger under `## QA summary`, then send it in your
message. Three parts, no diff reading required:

1. **What to test** — the observable behaviors, one line each, each
   mapping to the contract end-state lines it exercises.
2. **What changed** — the merges onto the run branch, in order, one
   line each.
3. **Known risks** — risk notes the plan flagged and what came of them,
   plus any item parked at the circuit breaker with its defect history.

## The gates

- **OK** → `steps/04-land.md`.
- **Defects** → each defect becomes a fix-cycle contract against the
  still-alive run branch; re-enter `steps/02-implement.md`. Parked
  items return with their new contracts. When fix cycles pass, present
  QA again — only the deltas, but the full gate every time.

## Done when

Done when: the human says OK, or a defect list is logged in the ledger
and dispatched as fix cycles.
