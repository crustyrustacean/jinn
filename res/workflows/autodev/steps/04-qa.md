# QA brief — the human's one contact per cycle.

## When

The tracker holds no claimable, dispatched, or triaged issue, no worker
is assigned, and every `open` issue is closed — the run branch carries
the whole goal and nothing is in flight. Before writing a single word,
re-scan the tracker: a stale brief costs a whole extra cycle.

## The brief

Post it as your reply to the human (plain text in the conversation, not
a file):

**What changed** — the run branch's log since the base branch, one line
per merge, in order.

**How it's supposed to work** — the root contract's end-state section,
restated as observable behavior. What the user does, what they should
see. This is the same bar the planner set, the implementor hit, the
reviewer judged, and you verified at the gate — the human is the last
reader of the same document.

**How to test it** — the shortest concrete path to exercising every
merged issue. Prefer the contracts' own verification commands, escalated
to human scale (the picker's confirm criterion becomes "open it, toggle
one, press ENTER, check the file and the live matcher"). If a
verification recipe from integration covers it, name it.

**Known state** — proposed issues workers filed that were not yet
triaged, abandoned workers, non-convergence refiles, anything that will
look odd.

**Proposed record entries** — durable repo-wide facts the pool
reported from this cycle's work, one line each, collected verbatim from
reports. The human approves or ignores; `.agents/RECORD.md` itself is
edited only after that approval, and never mid-run.

Then stop. The turn ends; the human reads, tests, and replies.

## On the human's reply

- **Defects** — each one becomes a new tracker issue, status `triage`.
  Then triage runs, the loop resumes, and no human is involved until
  the next brief. A defect is an issue, never a conversation. If the
  defect contradicts the root contract's end state, the planner's
  contract pass on the defect issue reconciles the two before
  implementation — the end state, not the defect, decides what
  "fixed" means.
- **OK** — run the land step.

The human never reviews code. Their QA is: does the thing work when I
do what the brief says. Recurring bugs across cycles are a signal for
more careful review next time, not a new gate this time.
